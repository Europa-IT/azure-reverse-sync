# azure-reverse-sync

PowerShell tooling to sync Azure AD / Microsoft Entra ID users to an on-premises Active Directory server, with full Kerberos authentication support for shared files and folders.

## Architecture

```
Azure AD
    │
    ├─► Entra Cloud Sync Agent  ──► on-prem AD  (cloud security group writeback)
    │   managed by this tooling
    │
    └─► This Tool (PowerShell)  ──► on-prem AD  (user attributes, account state,
        Invoke-AzureSync.ps1                     group memberships, PKINIT certs,
                                                  SPNs, keytabs)
```

**Two complementary pipelines:**

| Pipeline | What it handles |
|---|---|
| Entra Cloud Sync agent | Cloud security group writeback — provisions groups created in Azure AD into on-prem AD ([Microsoft docs](https://learn.microsoft.com/en-us/entra/identity/hybrid/cloud-sync/how-to-configure-entra-to-active-directory)) |
| This tool | User attributes, account enable/disable, group memberships, PKINIT certificate sync, SPN registration, keytab export |

> **Note — password and Kerberos key sync:** Microsoft Entra Cloud Sync does not
> synchronize password hashes or Kerberos keys from Azure AD to on-prem AD. That
> direction is not a supported scenario. For end-user Kerberos authentication, use
> PKINIT (certificate-based) as described below.

### Kerberos authentication paths

| Path | Mechanism | Dependency |
|---|---|---|
| End-user Kerberos TGT (certificate / PKINIT) | Azure AD certificate written to AD `userCertificate`; KDC authenticates via PKINIT — no password required | Entra CBA certs + `Sync-UserCertificates.ps1` |
| Service account (CIFS, NFS, etc.) | SPN registered in AD; keytab generated by `ktpass.exe` | `Set-KerberosSpn.ps1` — no password sync required |

## Prerequisites

- Windows Server, domain-joined to the on-prem AD domain
- PowerShell 5.1 or later (run as Administrator)
- RSAT: Active Directory Domain Services and LDS Tools
- `ktpass.exe` (included with AD DS tools; `Install-WindowsFeature RSAT-AD-Tools`)
- An Azure AD **App Registration** (service principal) with these Graph API permissions (Application, not Delegated):
  - `User.Read.All`
  - `Group.Read.All`
  - `GroupMember.Read.All`
  - `UserAuthenticationMethod.Read.All`
  - `Synchronization.ReadWrite.All`
  - `Application.Read.All`

Run the prerequisites installer to validate and install required PS modules:

```powershell
.\Install-Prerequisites.ps1
```

## Setup

### 1. Configure

```powershell
Copy-Item config\sync-config.example.json config\sync-config.json
# Edit config\sync-config.json — fill in TenantId, ClientId, AD server, OUs, etc.
```

Store your App Registration secret or certificate in **Windows Credential Manager** — never in `sync-config.json`.

### 2. Set up Entra Cloud Sync (one-time, for password/Kerberos key sync)

```powershell
# Step 1: Install the agent (requires installer pre-downloaded from Entra portal)
.\src\Invoke-AzureSync.ps1 -InstallAgent

# Step 2: Complete the registration wizard that opens (sign in as Hybrid Identity Admin)

# Step 3: Configure the provisioning job via Graph API
.\src\Invoke-AzureSync.ps1 -ConfigureCloudSync
```

Monitor provisioning status at: **Entra ID > Hybrid Management > Microsoft Entra Connect > Cloud Sync > Logs**

### 3. Dry-run preview

```powershell
.\src\Invoke-AzureSync.ps1 -DryRun
```

Logs all planned changes without writing to Active Directory.

### 4. First live sync

```powershell
.\src\Invoke-AzureSync.ps1
```

### 5. Schedule recurring sync

Create a Windows Task Scheduler task:

```powershell
$action  = New-ScheduledTaskAction -Execute 'powershell.exe' `
               -Argument '-NonInteractive -File "C:\azure-reverse-sync\src\Invoke-AzureSync.ps1"'
$trigger = New-ScheduledTaskTrigger -RepetitionInterval (New-TimeSpan -Minutes 30) -Once -At (Get-Date)
$settings = New-ScheduledTaskSettingsSet -RunOnlyIfNetworkAvailable
Register-ScheduledTask -TaskName 'AzureSync' -Action $action -Trigger $trigger `
    -Settings $settings -RunLevel Highest -User 'CORP\svc-azuresync'
```

## Usage

```powershell
# Full sync (default)
.\src\Invoke-AzureSync.ps1

# Dry run — no writes to AD
.\src\Invoke-AzureSync.ps1 -DryRun

# Sync users and groups only
.\src\Invoke-AzureSync.ps1 -SkipCertificates -SkipKerberos

# Kerberos SPNs + keytabs only
.\src\Invoke-AzureSync.ps1 -SkipUsers -SkipGroups -SkipCertificates
```

## Security

- **Secrets**: store client secret or certificate private key in Windows Credential Manager, not in `sync-config.json`
- **Keytabs**: ACL'd to the service account and Administrators only; never committed to git (`*.keytab` is gitignored)
- **PKINIT CA**: the issuing CA added to the NTAuth store can issue domain logon certificates — use a dedicated issuing CA, not a root CA
- **App Registration**: grant only the minimum Graph permissions listed above; do not use `Directory.ReadWrite.All`

---

## Password Hash Sync Limitation

The Microsoft Graph API does not expose password hashes. True synchronization of Kerberos key material requires the **Entra Cloud Sync agent**, which has privileged access not available to custom scripts. This tool's `Configure-EntraCloudSync.ps1` sets up that agent as a companion process.

If Entra Cloud Sync is not available in your environment, use **PKINIT** (certificate-based Kerberos) as an alternative — users authenticate with their Azure AD certificate rather than a password, completely bypassing the password sync issue.
